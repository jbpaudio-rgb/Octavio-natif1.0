# NOTES-K: modulation "listening" test (LFO 1-4, S&H 1-2, matrix lines) per engine

Branch `m6-K`. Everything below is **signal analysis of renders, not listening**, made with the host bench (`host/modtest.c`: the firmware's real sources
- engines, matrix `lfo.c`, effects - driven like the audio IRQ, blocks of 128) and the prototype's own engine classes run in node (`tools/proto_render.js`).
Never run on the real FM-1. The emulator was used for one end-to-end check (below).

## Method
* `tools/modhost.sh` builds the bench; `tools/modlisten.py` / `tools/modlisten2.py` render each case WITH and WITHOUT modulation, measure the targeted feature
  (pitch by zero crossings / autocorrelation, spectral centroid, rms, spectral peak for resonance, per-hit metrics for drums, onsets for lanes) and list every
  engine / FX / level parameter the matrix moved (`CHG`): only the target may move.
* `tools/modsweep.py ENGINE...`: exhaustive sweep, one LFO (sine, 1.7 Hz, amount 1) on every destination of the engine's list (283 destinations over the 4 engines), compared with the same render
  without modulation and with the prototype (similarity).
* Figures: `figures/*.png` (spectrogram + measured vs expected), wav pairs `audio/*_dry.wav` / `*_mod.wav` (same gain for both).

## Result of the sweep (all destinations of every engine list)
Vactrol 69, Minimoog 78, Prophet 81, Drums 55 destinations (lane settings dsw/dhu/dch/dac are tested with the step clock, below). In every case the sound changed,
the render without modulation is reproducible (0.0 dB) and **only the target parameter moved**. Exceptions, all identical in the prototype:
* Minimoog `rel`: no effect (prototype's Minimoog has no release use; the prototype's code ignores it too).
* Drums voice 4, `dtu4` and `dpe4`: no effect (that voice ignores tune / pitch envelope; same in the prototype, similarity 1.00).
* The FX destinations are not offered to the Drums track (the destination list of the prototype for drums has none): not a bug, by design.
* Low similarity with the prototype under heavy modulation (sim 0.66-0.8: Vactrol decay / atk, Minimoog and Prophet cutoff / sustain) is the nonlinear / chaotic response
  to a 100 % sweep, also present before my changes (checked on the original sources: mgcut 0.78, pcut 0.72 both before and after).

## Fixes made (minimal)
| # | Problem | Measured before | After | Where |
|---|---|---|---|---|
| 1 | Vactrol ignored note velocity (arp accent / humanize / sequencer) | found by the test, not quantified | follows velocity (vel15) | `vactrol.c`, `voices.c`, `params.h` |
| 2 | FM destination: matrix moved the knob linearly, but the engine uses knob^2 x 2 | found by the sweep vs prototype, not quantified | modulation applied in the squared domain like the prototype | `lfo.c` |
| 3 | Arp gate modulation range (0 .. 1 instead of the knob's .05 .. 1) | found by the sweep, not quantified | range .05 .. 1 | `lfo.c` |
| 4 | Drum voice killed too early / follower stall (Q15 follower) | found by the drum tests, not quantified | follower in Q23 | `eng_drum.c` |
| 5 | Level (track gain) stepped once per 128-sample block: zipper line at 344.5 Hz | -43.7 dB re carrier (6 Hz, amount 1), -47.3 dB (25 Hz) | **-74.3 / -85.3 dB** (gain ramps over the block) | `voices.c` |
| 6 | Pitch / cutoff written once per block: zipper lines | Moog cutoff -31.5 dB, Prophet cutoff -32.0, Vactrol pitch -39.5, Moog pitch -65.5 | **-55.0, -64.4, -62.5, -90.1** (values ramp across the block) | `eng_moog.c`, `eng_prophet.c`, `vactrol.c` |

Notes on 5/6: the metric is the strongest spectral line at f0 +- 344.5 Hz (the block rate) re the carrier, pure-ish tone, deep fast modulation. The prototype itself
steps its modulation once per audio buffer (512 frames in its ScriptProcessor), so it is not zipper-free either; the native build is now smoother. Moog cutoff at -55 dB
(+-2.8 octaves at 6 Hz) is still above the others; accepted. `sus` (sustain) and Vactrol `open` were not measured for zipper (the metric is not informative on those). The ramp costs a few
multiplies per 8-sample chunk (no 64-bit division); the CPU load was NOT re-measured (agent J's job).
The preset format is unchanged, no section rev bumped (no semantics change in stored data).

## What is NOT tested
* Never on the real FM-1 (no hardware); no human listening: all verdicts are measurements. Possible audible differences (grain of the filter ramps, noise floor of the reverb tail at about -72 dB, which is static) are unjudged.
* Per-track matrices: tested with 4 tracks active (each solo with the other matrices on: no cross-talk, 0.00 dB). Engine change with active mod (mod_fix) and mid-run engine switching not exercised.
* Zipper: Level, pitch (Vactrol, Moog, Prophet), cutoff (Moog, Prophet). Not measured: sustain, resonance, FX knobs, drum parameters (per-hit values, no block-rate signal).
* The prototype comparison uses the extracted engine classes at 128-frame blocks, not the browser's real scheduling.
* Sync (tempo-synced LFO rate) and the sequencer lines (qline) were exercised only by the sweep (Seq gate yes, other lines no).
* CPU: no new measure after the ramp edits.
* `tests/state_test.c`: ALL OK.
